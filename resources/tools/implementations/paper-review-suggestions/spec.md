# 论文修改建议

## 1. 功能概述

基于用户提供的 PDF 论文文件路径和投稿会议名称，调用【获取DeepSeek API KEY】系统API获取 DeepSeek 大模型 API_KEY，将 PDF 直接发送至 deep seek v4 pro 模型进行中文评审，按指定关注方面生成详细修改建议，并以系统当前时间作为评审时间，将评审报告保存为 Markdown 文件至论文同目录下，同时返回评审意见内容。

## 2. 输入规范

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| path | string | 是 | 无 | PDF 论文文件路径 |
| conf | string | 是 | 无 | 投稿会议名称，用于依据该会议评审标准进行评议和打分 |

## 3. 输出规范

### 3.1 标准输出字段
| 字段 | 类型 | 说明 |
|------|------|------|
| status | string | success / failed |
| message | string | 结果说明 |
| output_format | string | text |
| data | dict | 包含评审意见全文与报告文件路径 |

data 示例：
```json
{
  "text": "评审意见全文...",
  "report_path": "/path/to/论文名_评审报告.md"
}
```

### 3.2 可视化输出格式
| output_format | data 格式 | 界面渲染方式 |
|---------------|----------|-------------|
| `text` | `{"text":"评审意见全文", "report_path":"/path/to/report.md"}` | 纯文本展示评审意见，并附报告文件路径 |

## 4. 依赖环境

| 依赖 | 版本 | 用途 |
|------|------|------|
| openai | >=1.0.0 | 调用 DeepSeek 兼容接口进行模型评审 |
| requests | >=2.31.0 | HTTP 请求与文件上传 |

## 5. 运行机制

### 5.1 执行流程
1. 读取输入数据：获取 PDF 论文路径 `path` 和会议名称 `conf`。
2. 校验参数：检查 `path` 是否存在且为 PDF 文件，检查 `conf` 是否为空。
3. 调用【获取DeepSeek API KEY】系统API，获得 DeepSeek 大模型的 API_KEY。
4. 将 PDF 文件直接发送给 deep seek v4 pro 模型，并以中文按以下关注方面生成详细评审意见：
   - 总体创新性评估
   - 论文结构、形式、实验完整性评估
   - 摘要、简介与章节安排的一致性、衔接与呼应
   - 总体思路章节与贡献点、后续章节的对应关系
   - 公式目的解释与符号说明的清晰度
   - 消融实验完整性与核心参数敏感性分析
   - 实验充分性、baseline 方法先进性与完备性
   - 论文可读性与可复现性
   - 针对上述评估重点给出详细批改建议和指引
   - 按 `{conf}` 评审标准进行评议并给出最终打分判定
5. 评审时间使用系统当前时间。
6. 将评审意见写入 Markdown 文件，保存至与论文相同的目录下，文件名格式为 `{论文名}_评审报告.md`。
7. 返回评审意见全文及报告文件路径。

### 5.2 错误处理
- 文件不存在或路径无效 → 返回错误信息：`论文文件不存在或路径无效`。
- 文件不是 PDF 格式 → 返回错误信息：`仅支持 PDF 格式论文`。
- 会议名称为空 → 返回验证错误：`请提供投稿会议名称`。
- 获取 API KEY 失败 → 返回错误信息：`获取 DeepSeek API KEY 失败`。
- 模型调用失败或超时 → 捕获异常并返回详细错误信息。
- 报告写入失败 → 返回错误信息：`评审报告保存失败`。
