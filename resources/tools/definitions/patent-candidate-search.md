# 专利智能检索候选池

## 1. 功能概述

读取**本地待检专利/技术方案文件**，由大模型自动提取检索关键词（主关键词 + 次级关键词），
按用户给定的**国别 / 分类号 / 年份**硬约束**自动迭代检索** Google Patents：

- 第 1 次搜索：仅**主关键词**（相关专利必含的词，主关键词可有多个，之间是 AND 关系）；
- 第 2~5 次：逐个**追加**次级关键词，若顶部相关性变差则**换词**；
- 每次只取**第一页**（100 条），用大模型按「同一技术方向」筛出相关专利并保留；
- 5 次结束后**合并去重**（按公开号），返回**最相关的前 20 篇**（标题 + snippet + 公开号）。

> **注意**：本工具**不下载全文**，只返回候选池元数据。snippet 是关键词命中片段，**不是完整摘要**。
> 用户挑选后，用「专利检索下载」按公开号下载全文，再用「本地查重」做比对。

## 2. 与其它专利工具的关系

| 工具 | 职责 |
|------|------|
| 本工具（patent-candidate-search） | 自动迭代检索 + 候选池展示（不下载） |
| patent-search（专利检索下载） | 用户手动给关键词 + 下载前 N 篇全文 |
| patent-download-check（本地查重） | 待检文件 + 已下载目录 → 程序粗筛 + 大模型复核 |

三个工具并存，测试阶段互不替代。

## 3. 输入规范

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| path | string | 是 | - | 待检专利/技术方案文件（txt/md/pdf/docx） |
| country | string | 是 | CN | 国别代码 CN/US/EP/WO，输入 `0` 表示不限 |
| ipc | string | 否 | - | 分类号 CPC，如 B64U，输入 `0` 或留空表示不限 |
| date_from | string | 否 | - | 起始年份，输入 `0` 表示不限 |
| date_to | string | 否 | - | 截止年份，输入 `0` 表示不限 |
| max_rounds | int | 否 | 5 | 迭代搜索次数（硬上限，含首次，2~5） |

> 国别 / 分类号 / 年份是**硬约束**，迭代过程中不会被大模型修改。

## 4. 输出规范

| 字段 | 类型 | 说明 |
|------|------|------|
| status | string | success / failed |
| message | string | 迭代摘要（含主关键词/国别/分类号） |
| output_format | string | table |
| data.total_candidates | int | 合并去重后的候选数量（≤20） |
| data.candidates | list | 候选池，每项含 publication_number / title / snippet / assignee / country / url |
| data.columns / rows | list | 前端表格（序号/公开号/标题/snippet/链接） |
| data.rounds | list | 各次迭代日志（检索式、命中数、筛出数、相关性等级、调词动作） |
| data.core / secondary | - | 大模型提取的主关键词与次级关键词 |
| data.ipc | string | 用户显式输入的分类号（未输入则为空） |

## 5. 运行机制

1. `_read_document` 读待检文件。
2. `_extract_keywords` 大模型提取**主关键词**（相关专利必含，可 1~3 个，多个主词之间 AND）+ **次级关键词**（可能包含，按重要性排序）。**不提取分类号**，避免「猜」错 CPC 导致 0 结果。
3. **迭代搜索循环**（默认 5 次）：
   - 第 1 次：仅主关键词；
   - 第 2~5 次：逐个**追加**次级关键词；用户显式给的分类号用 `CPC=` 连接，国别/年份作独立参数；
   - 每次只取**第一页 100 条**（搜索走 `_gp_request`，已带节流延迟）；
   - 每次用大模型 `_ai_assess_relevance` 判断顶部结果与待检专利的**技术方向相关性**（A/B/C 三档），并筛出「同一技术方向」的相关专利序号；
   - **反馈调词**：相关性比上一轮**变差**（如 A→B）→ 用下一个次级词**替换**刚加入的词；相关性持平或更好 → 继续追加下一个次级词；
   - 无结果 → 退回最后一个次级词放宽。
4. **合并去重**：5 次筛出的相关专利按公开号去重（保序）。
5. **返回前 20 篇**：按「轮次顺序 × 轮内相关性序号」取最相关的前 20 篇作为候选池。

**相关性判定（技术方向，非关键词命中）：**
- 大模型判断每篇是否与待检方案「同一细分技术方向」，而非仅看关键词是否命中；
- 等级 A=高度相关 / B=部分相关 / C=基本无关；A→B 或更低视为「变差」触发换词。

**主/次关键词规则：**
- 主关键词：相关专利标题/摘要中**必含**，每次搜索都保留；**主关键词可有多个（1~3 个），多个主词之间是 AND 关系**（如「无人机」+「停机坪」要求两者都出现，用于精准限定主题）；
- **同义词扩展**：每个主词可带 0~3 个**等价替换词**（synonyms），检索式组内用 `OR` 连接（扩召回），组间用空格（AND）。实测：多关键词 AND 场景下 Google **不做同义归一**，故同义词对防漏检很关键；但同义词必须是等价替换词，禁止上位词/相关词；
- **英文短语引号处理**：含空格的英文短语（如 `solid state battery`）在检索式中必须用双引号包裹，否则空格会被 Google 误当 AND 分隔符，导致召回暴跌（实测 16866→1360）；代码已用 `_wrap_term` 自动加引号；
- 次级关键词：**可能包含**，用于逐步收窄到细分技术方向，用错则换。

**分类号处理：** 分类号仅在用户显式输入时作为硬约束生效；大模型不自动建议分类号。

## 7. 典型用法

- 「帮我分析 ./data/my.md 这份技术方案，找出相关的中国专利」
  → `path=./data/my.md, country=CN, ipc=0, date_from=0, date_to=0`
- 「分析交底书，限定 2018 年后的无人机相关专利」
  → `path=./data/disclosure.docx, country=CN, ipc=B64U, date_from=2018, date_to=0`

> 完整流程：本工具生成候选池 → 用户挑专利 → 「专利检索下载」下载全文 → 「本地查重」比对。
