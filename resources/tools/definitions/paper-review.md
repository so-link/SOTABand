# 论文评审

## 1. 功能概述

本工具基于系统统一配置的大模型（LLM）对学术论文 PDF 进行自动化评审。输入论文文件路径、目标会议名称及结果数据集名称，工具将调用语言模型（跟随全局 `LLM_PROVIDER` / `LLM_API_KEY` / `LLM_MODEL` 配置自动选择服务商，使用工具模板提供的 `_llm_chat` 辅助函数）从创新性、结构完整性、贡献一致性、可读性等维度进行详细评审，生成中文评审报告并保存为 Markdown 文件，同时自动将报告目录注册为数据集（若不存在）。

## 2. 输入规范

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| path | string | 是 | - | 待评审论文的 PDF 文件路径 |
| conf | string | 是 | - | 投稿的会议名称，用于匹配评审标准 |
| dataset | string | 是 | - | 评审结果输出数据集的名称 |

## 3. 输出规范

### 3.1 标准输出字段
| 字段 | 类型 | 说明 |
|------|------|------|
| status | string | success / failed |
| message | string | 结果说明 |
| output_format | string | text |
| data | dict | 输出数据 |

### 3.2 可视化输出格式
| output_format | data 格式 | 界面渲染方式 |
|---------------|----------|-------------|
| `text` | `{"text":"评审意见全文...", "report_path":"/path/to/report.md"}` | 纯文本展示，并提供报告文件链接 |

## 4. 依赖环境

| 依赖 | 版本 | 用途 |
|------|------|------|
| (内置) core.llm | - | 系统统一 LLM 客户端（跟随全局 LLM_PROVIDER / LLM_API_KEY / LLM_MODEL） |
| PyPDF2 / pdfplumber | ≥3.0 | PDF 文本提取（需先解析为纯文本再调用 LLM） |
| os | 内置 | 路径操作与文件存储 |

## 5. 运行机制

### 5.1 执行流程
1. 接收输入参数：论文 PDF 路径 `path`、会议名称 `conf`、数据集名称 `dataset`。
2. 将 PDF 解析为纯文本，使用工具模板提供的 `_llm_chat(messages, ...)` 调用系统统一 LLM 进行内容评审，评审要求包括：
   - （1）总体创新性评估；
   - （2）结构、形式、实验完整性评估；
   - （3）摘要、简介与章节安排的一致性和连贯性；
   - （4）总体思路章节与前后文的对应关系；
   - （5）公式目的及符号解释的清晰度；
   - （6）消融实验与核心参数敏感性分析；
   - （7）实验充分性及对比基线方法的先进性与完备性；
   - （8）论文可读性与可复现性；
   - （9）针对上述要点给出详细批改建议与指引；
   - （10）按 `{conf}` 的评审标准进行最终评议与打分判定。
3. 将模型返回的评审意见保存为 Markdown 文件，存储至项目目录 `./data/papers/{XXXX}/`（其中 `{XXXX}` 由工具根据论文文件名或时间戳自动生成）。
4. 通过系统 API **【获取数据集信息】** 查询数据集 `{dataset}` 是否存在。
5. 若数据集不存在，则通过 **【数据集注册API】** 将目录 `./data/papers/{XXXX}/` 注册为数据集 `{dataset}`。
6. 返回包含评审意见全文及报告文件路径的结果。

### 5.2 错误处理
- PDF 文件不存在或读取失败 → 返回错误信息，status=failed。
- 系统 API 调用失败（如数据集查询失败）→ 返回详细错误并建议检查网络或权限。
- LLM 请求失败或返回格式异常 → 捕获异常并返回具体错误描述。
- 目录创建或文件写入失败 → 返回文件系统错误。
