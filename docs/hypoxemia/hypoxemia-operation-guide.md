# 从零运行 SOTABand：低氧血症离线处理、训练与评测

本指南面向第一次取得项目源码的 Windows 用户：安装依赖、配置本机服务、启动网页，再完成数据处理、训练、保存模型、重新选择、评测和 Excel 下载。最后提供三个逐步操作示例及不含患者信息的演示数据生成命令。

“开始低氧预测”是进入离线工作流的口令，并不表示实时监测或自动给出临床诊断。本文覆盖平台启动和低氧工具；其他工具的专用依赖请查阅各自说明。当前交付方式是源码安装，不是双击即用的 EXE。

如果只使用平台的普通对话、资源空间等功能，不需要安装低氧计算环境。请改看[平台独立安装](hypoxemia-runtime-and-delivery.md#只安装平台不使用低氧预测)；本指南第 1.3 节的安装脚本会同时安装平台和低氧计算环境。

阅读顺序：[安装依赖](#1-下载之后先安装什么) → [启动前后端](#2-启动检查和关闭前后端) → [按钮与数据](#3-认识输入框卡片和数据) → [数据处理](#4-开始工作流并选择数据) → [训练与保存](#5-训练新模型从架构到保存权重) → [评测与下载](#6-重新选择模型评测和-excel)。遇到问题看[故障处理](#7-常见问题与恢复)，动手练习从[生成演示数据](#8-为三个完整例子生成演示数据)开始。

## 1. 下载之后先安装什么

### 1.1 电脑上准备的程序

| 项目 | 是否需要 | 用途与准备方式 |
| --- | --- | --- |
| Windows 64 位、PowerShell | 本指南需要 | 以下安装命令在 PowerShell 执行，不是在 Python 提示符或聊天框输入 |
| Git | 用 Git 下载时需要 | 从维护者给出的仓库和分支取得代码；也可解压完整源码包 |
| 可运行 `py` 的 Python | 引导安装需要 | 可从 python.org 安装 Python 3.12 及 Windows Python Launcher；脚本会另行准备固定版本 |
| uv 0.8.22 | 需要 | 管理 Python 和依赖，下一节给出安装命令 |
| Node.js 22.12 或以上的 22.x 版本，附带 npm | 从源码启动网页需要 | 从 nodejs.org 安装；Vite 要求 Node 20.19+ 或 22.12+，不要使用 Node 18 |
| 现代浏览器 | 需要 | 建议 Edge 或 Chrome，便于使用目录上传 |
| Excel 或支持 XLSX 的表格软件 | 查看导出表格时需要 | 不参与训练，不是后端依赖 |
| NVIDIA GPU、CUDA | CPU 入门不需要 | 首次按 CPU 方案运行即可；额外安装及未验证范围见[运行依赖说明](hypoxemia-runtime-and-delivery.md) |

首次安装需联网下载 Python、PyPI 包、PyTorch CPU wheel 和 npm 包。磁盘应容纳两套环境、安装缓存、原始数据、ZIP 解压副本和训练产物；实际占用随数据规模增加。

### 1.2 打开正确的项目目录

审查期间，使用包含内置低氧组件的 PR 分支：

```powershell
git clone --branch review/hypoxemia-builtin-20261011 --single-branch https://github.com/Trumam/SOTABand.git SOTABand
Set-Location .\SOTABand
```

该 PR 合并到你仓库的 `main` 后，新用户可改用 `git clone https://github.com/Trumam/SOTABand.git SOTABand`。若从别处取得完整源码包，在资源管理器中打开项目根目录，再在该目录打开 PowerShell。这里应能看到 `app`、`frontend`、`requirements`、`scripts` 等文件夹。

执行：

```powershell
Get-Location
Test-Path .\scripts\install_hypoxemia.ps1
py --version
node --version
npm --version
```

`Test-Path` 应返回 `True`。若返回 `False`，先切换到正确目录或取得正确版本。后文“仓库根目录”均指这个目录，不要求使用开发者原来的本机路径。

### 1.3 安装平台与低氧计算依赖

在仓库根目录执行：

```powershell
py -m pip install uv==0.8.22
uv --version
powershell -ExecutionPolicy Bypass -File .\scripts\install_hypoxemia.ps1
```

若提示找不到 `uv`，可指定由当前 Python 安装的程序路径：

```powershell
$uvProgram = Join-Path (py -c "import sysconfig; print(sysconfig.get_path('scripts'))") 'uv.exe'
powershell -ExecutionPolicy Bypass -File .\scripts\install_hypoxemia.ps1 -Uv $uvProgram
```

脚本下载 **Python 3.12.11**，建立两个环境，按锁文件安装全部依赖。无需逐个 `pip install`，也无需复制别人的虚拟环境：

| 环境 | 负责什么 | 主要固定依赖 |
| --- | --- | --- |
| `.venv-platform` | API、Agent、网页请求、任务及资源管理 | FastAPI 0.143.0、uvicorn 0.54.0、openai 3.28.0、pydantic 2.14.0；全部版本见 [platform.lock](../../requirements/platform.lock) |
| `.venv-hypoxemia` | 原始处理、PyTorch 训练及评测 | torch 2.5.1+cpu、numpy 2.1.3、pandas 2.2.3、scikit-learn 1.5.2、scipy 1.14.1、einops 0.8.1、reformer-pytorch 1.4.4、PyWavelets 1.8.0、matplotlib 3.9.2；全部版本见 [hypoxemia-cpu.lock](../../requirements/hypoxemia-cpu.lock) |

两个环境使用相同的 Python 版本。启动平台时使用第一个环境，平台自动调用第二个环境计算，**不需要手动切换到另一个环境启动训练**。低氧处理代码和模型实现已经内置，不需要下载独立研究项目，也不需要配置 `SPO2_HYPOXEMIA_PROJECT`。

安装后核对：

```powershell
.\.venv-platform\Scripts\python.exe --version
.\.venv-hypoxemia\Scripts\python.exe -c "import torch; print(torch.__version__)"
```

预期分别包含 `3.12.11`、`2.5.1+cpu`。已有同名环境但 Python 版本不符时，安装器会停止；可在新的源码目录安装，不要覆盖正在使用的环境。

普通使用不需要 pytest。开发者运行验收时可给安装命令加 `-WithVerification`，具体方法见 [pr-readiness.md](pr-readiness.md)。

### 1.4 安装前端依赖

在仓库根目录执行：

```powershell
Push-Location .\frontend
npm ci
Pop-Location
```

`npm ci` 按 `frontend/package-lock.json` 安装网页依赖。每次启动不用重装，更新前端依赖锁文件后再执行。若 PowerShell 阻止 `npm.ps1`，可以把命令中的 `npm` 换成 `npm.cmd`。

### 1.5 配置本机 LLM API

在仓库根目录执行，已有 `.env` 时保留原文件：

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
notepad .env
```

根据自己的服务商设置以下键：

| 键 | 填写内容 | 作用 |
| --- | --- | --- |
| `LLM_PROVIDER` | `.env.example` 中支持的服务商名称 | 选择服务商预设 |
| `LLM_API_KEY` | 自己申请的 API Key | 授权调用对话模型 |
| `LLM_BASE_URL` | 服务商给出的兼容 API 地址 | 可选覆盖；不要填普通官网页面地址 |
| `LLM_MODEL` | 当前账号可调用的模型名称 | 可选覆盖；服务商模型名称不同 |

这些配置用于平台对话、自由描述及“其它（交给大模型）”等入口；离线训练本身不调用 LLM。健康接口成功不代表 API Key 已验证，可发一条普通对话检查服务配置。要完整使用平台，请准备有效的 API 配置。Key 只保存在本机，不要发到聊天框或提交到 Git。

修改后重启后端才生效。终端中同名环境变量优先于 `.env`；`SOTABAND_LOAD_DOTENV=0` 会禁用读取 `.env`，正常启动不要沿用验收终端中的这个设置。

### 1.6 可选：设置产物目录

默认运行根目录为仓库下 `.runtime/refactor`，保存任务、处理数据、模型登记和评测输出。新用户可以直接使用默认值。需要换到数据盘时，在**启动后端的终端中**设置：

```powershell
$env:SOTABAND_RUNTIME_ROOT = 'E:\SOTABand-data'
```

替换为自己可写的目录。该命令只影响当前终端启动的进程；也可写入本机 `.env` 持久保存。更换运行根目录会切换任务和资源列表，不会自动迁入旧模型。备份要同时保留登记信息和实际产物，不能只备份模型 ID。

手动输入其他数据目录不必逐个加入白名单，也不需要设置 `SPO2_HYPOXEMIA_TRUSTED_DATA_ROOTS`。

## 2. 启动、检查和关闭前后端

### 2.1 终端 A：后端

在仓库根目录执行，并保持终端打开：

```powershell
.\.venv-platform\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8002
```

浏览器打开 `http://127.0.0.1:8002/api/health`，应返回 `{"status":"healthy"}`。

### 2.2 终端 B：前端

另开一个 PowerShell，同样先进入仓库根目录，再执行：

```powershell
Set-Location .\frontend
$env:SOTABAND_API_PORT = '8002'
npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

打开 **http://127.0.0.1:5174**。再访问 `http://127.0.0.1:5174/api/health`，也应得到健康结果，说明网页代理连到了当前后端。前端终端同样需要保持打开。

端口占用时 `--strictPort` 会报错，不会悄悄更换端口。可以关闭自己之前启动的同一服务，或同时更改后端 `--port` 和前端 `SOTABAND_API_PORT`。网页端口改变后访问相应地址。不要因端口冲突随意终止其他项目进程。

`npm run build` 只构建网页文件，不会启动此处的开发服务器；不能双击 `frontend/index.html` 代替启动。

### 2.3 下次启动和正常关闭

依赖与 `.env` 保留后，下次只需执行终端 A、B 的启动命令。关闭网页不会取消后台任务。要取消处理或训练，先点击任务卡片“停止”，等待状态变化。结束使用时，在两个服务终端分别按 `Ctrl+C`。

后端重启后需要重新进入交互流程；已保存的数据和模型可从原运行目录重新选择。不要在计算中途关闭后端作为正常取消方法。

## 3. 认识输入框、卡片和数据

### 3.1 通用按钮与操作

| 按钮或操作 | 会发生什么 | 需要区分的事项 |
| --- | --- | --- |
| 发送按钮 / Enter | 发送当前文字和已准备好的附件 | 上传结束后还需要发送，才进入工作流 |
| Shift+Enter | 在输入框换行 | 不发送消息 |
| 卡片编号或名称 | 选择当前步骤的一个候选 | 编号随资源数量变化，不套用旧截图编号 |
| 其它（交给大模型） | 通常进入自由描述；架构和训练参数阶段会先进入参数输入 | 不是默认选项，具体后果见下方各阶段说明，也不保证任意需求已有实现 |
| 文件夹图标“选择五通道数据目录” | 选择目录并上传配套窗口文件 | 浏览器的本地目录不等于服务器目录 |
| 回形针“选择本机数据文件” | 打开文件选择器，可同时选多个配套文件 | “选择本机文件”文字选项只是提示，仍需点击图标 |
| 附件旁 `×` | 从待发消息移除附件引用 | 不删除本机原始文件 |
| 输入框旁红色方块 | 中止当前回复流 | 不等于取消已经提交的后台处理/训练任务 |
| 任务卡片“停止” | 请求取消排队或运行中的任务 | 不是暂停；取消后不能从同一进度继续 |
| 查看最近日志 | 查看该任务最近的计算日志 | 不重新执行任务 |
| 完整返回数据 | 展开结果详情 | 不再次执行计算 |
| 下载评测 Excel | 下载本次已生成的 XLSX | 不重新训练或评测 |

每次操作**最后一张等待选择的卡片**。旧卡片还在聊天记录中，但当前工作流可能已经进入下一步。重新发送“开始低氧血症预测”会重开数据选择，不会自动取消已有后台任务。

### 3.2 原始数据与已处理数据

| 类型 | 你提供什么 | 平台做什么 |
| --- | --- | --- |
| 原始数据 | 符合监护数据布局的 CSV 目录，或保留该布局的 ZIP | 解压、清洗、分段、生成窗口和标签、登记数据 |
| 已处理数据 | 同一批窗口文件，或已登记数据集 ID | 检查数据，进入训练/评测，不重复处理 CSV |

原始文件不能仅因扩展名是 CSV 就认为兼容。演示 ZIP 的布局为：

```text
synthetic-monitor.zip
  synthetic/monitor___000/ParameterData/ParameterData-1s-synthetic.csv
  synthetic/monitor___001/ParameterData/ParameterData-1s-synthetic.csv
  ...
```

CSV 需要正确的时间和 `SpO2、HR、PR、RR、PI` 列，并符合处理器要求。原始目录推荐填写后端可访问的路径；从另一台电脑使用浏览器时上传保留层级的 ZIP，避免逐个上传 CSV 后丢失目录结构。

已处理数据文件如下：

| 文件 | 内容与要求 |
| --- | --- |
| `window_features.pkl` | 窗口数组；五个数值通道依次是 `SpO2、HR、PR、RR、PI`，可另有 `Time` 列 |
| `window_info.pkl` | 与窗口逐一对应的标签、通道说明及分组信息，如 `group_id` |
| `window_stats.json` | 窗口数量、采样率、声明窗口长度等 |
| `dataset_manifest.json` | 来源和输入规格清单；生成数据应连同它一起保留 |

前两个文件必须配套；统计文件或清单必须提供必要的输入规格，不能只靠文件名推断。建议四个文件一起使用，不混用不同批次的同名文件。默认示例是 1 Hz、256 秒窗口，即每个窗口 256 个时间点，预测间隔 30 秒。

`pickle` 是 Python 数据保存格式，读取时可能执行文件内包含的指令。因此请使用自己生成或已确认来源的文件，不加载不明来源的 `.pkl`。

## 4. 开始工作流并选择数据

在网页中央聊天输入框发送：

```text
开始低氧血症预测
```

| 第一步选项 | 后果 |
| --- | --- |
| 原始数据 | 提示提供目录或 ZIP，然后设置处理参数 |
| 已处理数据 | 显示已登记数据列表以及上传、路径入口 |
| 其它（交给大模型） | 说明其他需求，由 LLM 协助 |

### 4.1 已处理数据的三个来源

| 选项 | 操作与结果 |
| --- | --- |
| 列表中的数据名称 | 选中对应 ID 并检查文件，不重新处理原始数据 |
| 选择本机文件 | 点击后再点回形针，一次选中同一目录的四个配套文件，等上传结束后点击发送 |
| 输入路径或数据集 ID | 下一条消息输入后端可访问的完整目录、`window_features.pkl` 路径，或实际存在的数据集 ID |

也可用文件夹图标选完整窗口数据目录。数据列表显示类似 `balanced_windows_256s_30s_all（总数据量 163 个窗口，处理时间 2026-10-10 21:06）`。数量是**窗口数，不是患者数或原始行数**；时间精确到分钟。旧数据时间可能取自已有元数据或文件修改时间，同名同分钟的数据仍应核对 ID 和路径。

本机启动时直接粘贴 Windows 路径即可，不必加引号。远程浏览器填写自己电脑的路径不会自动上传文件，应使用上传入口。一次上传只选择一批配套窗口文件；不相关文件可能被过滤。

### 4.2 原始数据的完整操作

1. 选择“原始数据”，输入原始目录或 ZIP 的完整路径。也可点回形针上传 ZIP，上传结束后发送。
2. 如果提示提供 `staging_root`，填写独立的临时解压目录。不能与原始目录相同，也不能位于原始目录内。
3. 选择默认处理参数，或修改后提交。
4. 点击或发送“开始处理”。此前填写路径和参数不会启动计算。
5. 等任务显示“已完成”，点“扫描处理结果”，或在当前流程回复“继续”。
6. 检查数据摘要，再选择训练新模型或评测已训练模型。

例如原始目录为 `E:\monitor\raw`，可用 `E:\monitor\staging`，不可用 `E:\monitor\raw` 或 `E:\monitor\raw\staging`。需要同时为解压副本及处理输出预留空间。

**原始处理成功后会自动登记到数据列表。** “扫描处理结果”读取本次产物并推进当前对话，不会再处理一次。直接检查任意外部窗口目录不等于自动永久登记所有外部数据，之后可再次输入路径使用。

### 4.3 原始处理按钮与全部字段

| 操作 | 后果 |
| --- | --- |
| 使用默认处理参数 | 准备下表默认值，等待“开始处理” |
| 修改处理参数 | 打开表单，也可发送 JSON |
| 提交处理参数 | 校验并记录本次配置；留空恢复默认值，不启动任务 |
| 开始处理 | 使用确认的输入和配置提交后台任务 |

布尔值用 `true` / `false`，小数用小数点，列表用 JSON 数组。精确复现时优先使用表单或 JSON。

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `configs` | `["256:30"]` | `窗口秒数:预测间隔秒数`；例如 `["180:60"]`。改变输入长度；入门用单个配置，多配置任务目前主要展示、登记主输出 |
| `min_segment_seconds` | `600` | 原始连续记录最短秒数，更短的丢弃 |
| `spo2_threshold` | `94` | 低氧 SpO2 阈值，按百分比数值填写 |
| `hypo_operator` | `le` | 通用比较方式；`le` 为 ≤，`lt` 为 <。具体阶段另有两个比较参数，不要以为改这一项就改了全部阶段 |
| `hypoxemia_duration_seconds` | `20` | 预处理识别连续低氧段所需最短秒数 |
| `min_hypo_duration_seconds` | `20` | 窗口低氧标签判定所需最短低氧时长 |
| `max_non_hypo_ratio` | `2.0` | 控制非低氧相对低氧的采样比例；最终数量还受质量筛选、去重、可用窗口影响，不保证严格等于 2:1 |
| `nan_ratio_threshold` | `0.1` | 缺失比例上限，范围 0–1 |
| `pi_threshold` | `0.3` | 低 PI 质量判定阈值 |
| `low_pi_ratio_threshold` | `0.3` | 允许低 PI 样本比例上限，范围 0–1 |
| `drop_spo2_na_before_segment` | `false` | 是否先删除 SpO2 缺失行，会影响时间连续性 |
| `spo2_na_break_segment` | `true` | 保留的 SpO2 缺失行是否切断连续片段；已删除的行不再触发一次切分 |
| `crop_seconds` | `30` | `crop` 模式两端裁剪的秒数，不是所有边缘模式都会应用 |
| `edge_trim_mode` | `zhang` | `zhang` 保留首个至末个 SpO2 ≥ 阈值之间的记录，找不到合格点时丢弃；`crop` 按秒数裁剪，`none` 不做边缘裁剪。表单提示较简略，示例用 JSON 设置 `none` |
| `fill_method` | `interpolate` | `interpolate` 线性插值，`mean` 均值填补；缺失过多仍会被拒绝 |
| `apply_physiologic_bounds` | `true` | 将内置生理范围以外的数值置为缺失，再进入缺失筛选和填补 |
| `preprocess_hypo_operator` | `lt` | 预处理低氧比较方式，可用 `lt` / `le` |
| `window_hypo_operator` | `le` | 窗口标签低氧比较方式，可用 `lt` / `le` |
| `seed` | `42` | 处理时随机采样种子 |

例如发送：

```text
原始处理参数：{"configs":["256:30"],"edge_trim_mode":"none","crop_seconds":0,"seed":42}
```

### 4.4 检查结果与后续选项

核对数据 ID、路径、生成时间、窗口总数、正负类数量、序列长度、采样率和分组信息。默认示例应为 256 点、256 秒、1 Hz。通道顺序也必须匹配。基础检查通过后，计算仍会检查实际数组，不能仅凭文件存在就认定完全兼容。

| 选项 | 后果 |
| --- | --- |
| 选择模型架构并训练 | 设置实现、架构、训练参数，生成新产物 |
| 选择已训练模型进行评测 | 使用已有权重跳过训练；没有已保存模型时会提示先训练 |

## 5. 训练新模型：从架构到保存权重

### 5.1 选择架构

| 候选类型 | 后果 |
| --- | --- |
| 目录模型，如 SegRNN、DLinear、TimesNet | 选择内置实现并显示参数；首次建议 SegRNN |
| 已有模型资源：某个名称 | 读取保存过的配置，作为训练起点；配置不等于权重 |
| 已有自定义模型：某个名称 | 读取自定义资源；只有存在可执行实现才能训练 |
| 创建新的模型 | 等待描述名称、基础模型或新结构、编码器、时序聚合、分类头及训练设置；全新结构先登记为设计资源，不会凭描述自动变成已验证代码 |
| 其它（交给大模型） | 与创建入口一样，进入自定义模型描述，由 LLM 协助整理 |

各模型会改变网络实现、内存占用和训练时间。默认 CPU 安装的架构列表展示 38 个经过合成张量计算检查的可训练模型；这不等于逐模型完成了整轮训练或医学效果验证。上游未实现分类的 `KANAD`、`MultiPatchFormer`、`TiDE`、`WPMixer` 不再列为可训练架构。`MambaSingleLayer`、`SegRNNMambaFusion` 需要额外 CUDA 扩展，默认也不展示。

选择 `TimeMixer` 等多尺度模型时，应在架构详情核对 `down_sampling_layers=2`、`down_sampling_window=2`。旧版本保存的 TimeMixer 配置可能仍含 `0/1`，不能直接训练；可选择目录中的 `TimeMixer` 使用修正后的默认值，或在旧配置的架构修改步骤明确设置 `{"down_sampling_layers":2,"down_sampling_window":2}`。架构配置 ID 只代表参数，不包含已训练权重。

### 5.2 架构详情和按钮

“当前模型架构详情”是展示卡片。修改时选择“修改架构参数”，再发 JSON 或自然语言，不是点击详情里的数字直接编辑。

| 选项 | 后果 |
| --- | --- |
| 使用当前架构参数 | 保留配置，进入是否保存架构的选择 |
| 修改架构参数（层数、维度、注意力头等） | 等待输入，例如 `架构参数：{"d_model":32}` |
| 完成架构设置，进入训练参数 | 结束本轮编辑，先选择是否保存架构，再进入训练参数 |
| 继续修改架构参数 | 返回输入，可继续修改覆盖项 |
| 注册当前模型配置 | 立即登记可复用配置，返回配置 ID 并进入训练参数；没有生成权重 |
| 保存架构配置 | 登记架构以便以后复用，进入训练参数 |
| 本次使用，不保存架构配置 | 只用于当前训练，不新增配置资源 |
| 其它（交给大模型） | 在架构阶段进入架构参数输入，可发送自然语言或 JSON，不直接启动训练 |

字段是否生效取决于模型实现。共用详情可能包含模型未使用的字段，例如改变 SegRNN 的 `d_layers` 不能理解为增减 SegRNN 的解码器层数。

| 架构字段 | 含义 |
| --- | --- |
| `d_model`、`d_ff` | 隐藏表示、前馈层维度，增大通常增加计算量 |
| `dropout`、`activation` | 丢弃比例、激活函数 |
| `embed`、`freq` | 嵌入方式、时间编码频率；`freq` 不会重采样输入数据 |
| `n_heads`、`e_layers`、`d_layers` | 对应注意力/编码器/解码器的头数和层数，需满足模型维度约束 |
| `factor`、`distil`、`individual` | 部分模型的注意力因子、蒸馏及分通道开关 |
| `patch_len`、`stride`、`seg_len` | 模型内部 patch、步长和片段长度；不同于原始处理的窗口秒数 |
| `moving_avg`、`top_k`、`num_kernels` | 移动平均窗口、主要周期数、多核卷积数 |
| `channel_independence` | 部分 Mixer 模型的通道独立处理设置 |
| `down_sampling_layers`、`down_sampling_window`、`down_sampling_method` | 内部下采样层数、窗口及方式 |
| `use_norm`、`decomp_method` | 归一化与序列分解方式 |
| `alpha`、`top_p`、`pos` | 部分模型的系数、筛选或位置设置，没有跨模型统一含义 |
| `node_dim`、`gcn_depth`、`propalpha` | 图模型节点维度、传播深度、传播系数 |
| `conv_channel`、`skip_channel`、`subgraph_size` | 图/卷积模型通道数及子图规模 |
| `ratio`、`expand`、`d_conv` | 部分模型的比例、状态空间扩展倍数、卷积宽度 |
| `p_hidden_dims`、`p_hidden_layers` | 对应投影/隐藏网络的维度列表和层数 |

首次先用默认架构，或使用本文示例的 SegRNN `d_model=32`，不要同时修改大量专用字段。

### 5.3 训练超参数：选项和全部字段

| 操作 | 后果 |
| --- | --- |
| 使用默认训练超参数 | 使用默认配置并显示摘要，等待开始；默认 140 轮，不是短演示 |
| 修改训练超参数 | 打开表单，也可发 JSON |
| 提交训练参数 | 校验并记录，空白恢复默认值，不立即训练 |
| 其它（交给大模型） | 在训练参数阶段进入文字参数输入，支持自然语言或 JSON |
| 开始训练 | 按最终摘要提交后台任务，返回任务 ID |

修改后以回复中的最终配置为准。

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `optimizer` | `adamw` | 支持 `adamw`、`adam`、`sgd`、`rmsprop` |
| `learning_rate` | `0.00025` | 初始学习率 |
| `weight_decay` | `0.00005` | 权重衰减 |
| `batch_size` | `32` | 每批窗口数；内存不足可降低 |
| `epochs` | `140` | 最大轮数，入门设 `1`；早停可能提前结束 |
| `seed` | `42` | 训练随机种子 |
| `pos_weight_scale` | `0.7` | 正类损失权重比例，不修改标签数量 |
| `label_smoothing` | `0.015` | 标签平滑强度 |
| `grad_clip_norm` | `4` | 梯度范数裁剪阈值 |
| `use_ema` | `true` | 是否使用参数指数移动平均 |
| `ema_momentum` | `0.99` | EMA 平滑系数；关闭 EMA 后不生效 |
| `early_stop_patience` | `35` | 无改善容忍轮数；`0` 不表示关闭，达到起始检查轮次后即可停止。本文 1 轮演示不会触及默认第 25 轮的检查 |
| `early_stop_start_epoch` | `25` | 开始检查早停的轮数 |
| `selection_monitor` | `auc` | 最佳模型选择指标：`auc`、`accuracy`、`loss` |
| `reduce_lr_patience` | `4` | 降低学习率前等待无改善的轮数 |
| `reduce_lr_factor` | `0.5` | 降低学习率的乘数 |
| `min_lr` | `0.000005` | 学习率下限 |
| `lr_monitor` | `loss` | 调度监测指标：`loss`、`auc`、`accuracy` |
| `threshold_metric` | `f1` | 选择分类阈值的指标：`f1`、`accuracy`、`balanced`；评测重用保存的阈值 |

可复制的短训练输入：

```text
训练参数：{"epochs":1,"batch_size":8,"use_ema":false,"early_stop_patience":0}
```

配置已记录后，再发送：

```text
开始训练
```

### 5.4 等待任务及保存模型

| 状态或操作 | 意义与下一步 |
| --- | --- |
| 排队中、运行中 | 等待，不重复提交 |
| 停止 | 请求取消，等待“已取消”；不能暂停后继续 |
| 已完成 / 100% | 计算和完成处理成功；点“保存训练模型”，或回复“继续” |
| 失败 | 看错误和最近日志；提交成功不等于训练成功 |
| 已取消 | 本次不再继续，需要训练时重开流程 |

完成后选择：

| 选项 | 后果 |
| --- | --- |
| 保存训练模型到模型空间 | 登记实际产物，返回已训练模型 ID，以后可从列表重新选择；随后进入指标设置 |
| 仅本次评测，不保存训练模型 | 当前流程仍可评测，但不登记到已训练模型列表；不会自动删除磁盘产物 |

记下**已训练模型 ID**，不要与“保存架构配置”的 ID 混淆。重载依赖整套权重、scaler、配置、阈值报告和 manifest；只保留 `best_model.pt` 或只记住 ID 都不够。

## 6. 重新选择模型、评测和 Excel

### 6.1 使用已保存模型

重新进入流程，先选择**本次评测的数据**并检查，再点“选择已训练模型进行评测”。点击已保存模型，或输入其准确 ID；不能用架构配置 ID 代替。

| 已训练模型选项 | 后果 |
| --- | --- |
| 进入评测流程 | 使用所选模型进入指标和输出设置，不重新训练 |
| 删除此模型资源 | 删除登记及资源说明，从列表移除；当前实现不同时删除训练产物目录。这不是“退出选择” |
| 其它（交给大模型） | 描述额外需求，由 LLM 协助 |

某些旧资源入口还可能显示“直接评测已有模型”和“修改参数并重新训练”。前者与“进入评测流程”相同；后者返回架构/训练流程，产生新产物，不会直接修改原有权重。

### 6.2 指标选择

| 选项 | 含义 |
| --- | --- |
| 全部指标（默认） | 请求报告中全部可用指标，首次建议选它 |
| AUC | 两类窗口的排序区分能力 |
| AUPRC | 精确率与召回率曲线下面积 |
| F1 | Precision 和 Recall 的调和平均 |
| Accuracy | 评测窗口中分类正确的比例 |
| Balanced Accuracy | 各类召回率的平均，减少类别数量不均衡的影响 |
| Precision | 判为低氧的窗口中实际低氧的比例 |
| Recall | 实际低氧窗口被识别的比例 |
| MCC | 综合混淆矩阵的相关系数 |
| 其它（交给大模型） | 描述其他关注指标；可用性取决于实际报告 |

选单项是指定重点展示指标，不重新定义标签或训练方式。验证集只有一种类别时某些指标无法有效计算，缺失不代表性能为零。

### 6.3 输出和执行按钮

| 选项/按钮 | 后果 |
| --- | --- |
| 评测并导出 Excel | 设置生成表格，仍需点击开始 |
| 仅显示评测结果 | 展示结果，不生成本次 XLSX |
| 开始评测 | 加载所选模型，对所选数据做兼容性检查和计算 |
| 下载评测 Excel | 成功且选择导出后出现，下载当前结果 |

评测目前等待计算返回，不是训练任务那样的可取消进度卡。不要重复发送开始命令。如果先选了“仅显示”又想要 Excel，可重新进入评测并选择导出；“完整返回数据”不会自动生成表格。

### 6.4 为什么总窗口数与评测窗口数不同

训练默认按 `group_id` 分组划分，随机种子为 42，验证集和测试集目标比例各为 15%；受分组约束，窗口数不一定恰好为 15%。页面评测使用**所选数据集的验证划分**，测试部分保留作独立最终测评。即使选择另一批评测数据，也不自动评测这批数据的全部窗口。

评测重用模型保存的 scaler 和分类阈值，不偷偷重新训练。通道顺序、采样率、声明窗口长度及实际数组长度必须匹配，不会静默截短或补齐后返回指标。

成功后核对模型 ID、数据 ID/路径、输入总窗口数和验证集窗口数。Excel 包含汇总指标和来源信息，不是逐窗口预测明细。用表格软件打开确认后记录模型、数据来源及时间。

## 7. 常见问题与恢复

| 现象 | 处理方法 |
| --- | --- |
| `py`、`node`、`npm` 不存在 | 安装程序后重开终端，不在错误环境里临时补包 |
| 缺少 torch | 检查计算环境安装和解释器；平台环境本来就不要求 PyTorch |
| 后端正常，网页 `/api/health` 失败 | 核对代理端口，设置 `SOTABAND_API_PORT` 后重启前端 |
| HTTP 502 / 进度刷新失败 | 表示当时网页访问后端失败，不直接等于计算失败；查后端健康和终端，再按任务 ID 看状态，不立即重复提交 |
| 参数已记录却没训练 | 还需发送“开始训练”；原始处理需“开始处理” |
| 路径或资源不存在 | 检查后端可访问性、当前运行目录、当前用户可见资源；新检出不会自带别人机器上的数据列表 |
| staging_root 错误 | 选择源目录以外的独立解压目录，再确认任务 |
| 没有生成窗口 | 查原始布局、记录时长、标签、质量阈值和最近日志 |
| 模型缺少产物/manifest/输入规格 | 确认选择已训练模型并保留整套产物；旧资源需按可信信息补录或重新训练，不能猜值填入 |
| 输入不匹配 | 选择兼容模型或按目标规格重新处理并训练，不只修改统计文件掩盖真实形状 |
| 文字说完成但返回 `status: failed` | 以失败信息为准，本次没有有效结果，记录完整提示及 ID |
| 保存的模型不见了 | 检查运行目录、服务端口、当前用户、是否删除登记 |
| 没有下载按钮 | 确认导出选项和评测成功；“仅显示”不会生成本次 Excel |
| 中文乱码 | 文档与源码用 UTF-8 打开；PowerShell 阅读时用 `Get-Content -Encoding UTF8`，不依据乱码内容改数据 |

求助时提供步骤、时间、任务 ID、模型 ID、数据集 ID 和错误摘要，不附 API Key 或无关原始数据。验证范围见 [pr-readiness.md](pr-readiness.md)。

## 8. 为三个完整例子生成演示数据

以下例子使用仓库脚本生成的合成输入，不依赖旧电脑的目录或模型，只验证流程，不用于判断医学预测能力。

安装完成后，在仓库根目录执行：

```powershell
.\.venv-hypoxemia\Scripts\python.exe .\scripts\create_hypoxemia_demo_data.py --output .runtime/hypoxemia-demo
```

脚本只生成输入文件，不启动训练、不登记模型、不调用 LLM。输出目录存在时拒绝覆盖：可继续用已生成的数据，或换一个新的 `--output` 目录，不必删除旧数据。

脚本打印四个绝对路径，另存为 `demo-paths.json`。可分别显示并复制：

```powershell
$demoPaths = Get-Content -Raw -Encoding UTF8 .runtime/hypoxemia-demo/demo-paths.json | ConvertFrom-Json
$demoPaths.raw_zip
$demoPaths.staging_root
$demoPaths.processed_train
$demoPaths.processed_evaluation
```

| 输出 | 内容与用途 |
| --- | --- |
| `raw_zip` | 24 个合成监护设备，每个 1,200 秒；示例一的 ZIP |
| `staging_root` | 独立解压目录路径，处理时创建 |
| `processed_train` | 48 个窗口，24 低氧、24 非低氧；示例二上传 |
| `processed_evaluation` | 另行生成的 60 个窗口，30 低氧、30 非低氧；示例三评测 |

下文“粘贴 raw_zip”指粘贴输出的真实路径，**不要把变量名或 `$demoPaths.raw_zip` 发到聊天框**。文件中有数据集 ID 不等于已经登记；生成的窗口首次按路径或上传使用。

## 12. 示例四：创建新的模型资源 → 复用 SegRNN 实现 → 短训练

### 12.1 “创建新的模型”按钮做什么

“创建新的模型”不是立即生成 PyTorch 代码，也不是立即开始训练。它打开模型设计入口，让你说明模型名称、模型来源、输入、编码器、时序聚合、分类头和训练设置。系统随后按模型来源分两条路径：

| 模型来源 | 创建后的状态 | 能否继续训练 |
| --- | --- | --- |
| 已有目录模型，例如 `SegRNN`、`DLinear` | 创建一个带新名称的模型配置资源，复用仓库内已有实现，只保存受约束的架构/训练覆盖项 | 可以。进入架构确认和训练参数步骤后即可训练 |
| 已有模型资源 ID | 以该资源的配置为起点创建派生配置，原资源和原权重不被修改 | 可以，前提是来源配置和实现仍可用 |
| 自定义结构 | 先登记设计说明；系统不会把文字描述当成可执行代码 | 不能直接训练，必须先实现并验证对应 PyTorch 模型 |

配置资源 ID 只代表模型结构和训练设置，不代表 `best_model.pt`。只有训练完成并选择“保存训练模型到模型空间”后，才会产生可在评测入口重选的已训练模型资源。

### 12.2 可直接复制的操作

本例需要先完成数据检查，使用第 8 节生成的 `processed_train` 路径或数据集 ID。为避免把“设计资源”和“训练权重”混淆，本例选择已有 `SegRNN` 作为实现来源，并创建一个新的配置名称。

### 12.3 重要区别和失败情况

- 选择“本次使用，不保存架构配置”只是不登记配置，仍可训练；选择“保存架构配置”会登记可复用配置。
- 保存架构配置不会生成权重，不能直接从“选择已训练模型进行评测”入口使用。
- 如果描述“模型来源：自定义结构”，系统会登记设计资源并停止在设计阶段；这不是失败，而是防止未实现的文字结构被误当成可执行模型。
- 如果基础模型不存在、字段超出范围或模型实现不支持分类，系统会在登记/提交训练前返回错误，不启动计算任务。
- 训练成功后保存的是独立产物；原来的 `SegRNN` 配置和权重不会被修改。

本例完成后的核对项：配置资源 ID 出现在“模型架构与配置”，训练保存后产生另一个已训练模型 ID；两者可以同时存在，且只有后者可以进入评测流程。
