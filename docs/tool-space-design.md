## 一、概述

### 1.1 设计目标

将当前的工具管理从「平铺列表」升级为「仓库 + 工作空间」双层架构，支持工具的规模化管理和按需加载。

### 1.2 核心概念

| 概念 | 定义 | 存储位置 | 类比 |
|------|------|---------|------|
| **工具仓库** | 系统中所有已创建工具的全局注册中心，可删除 | 「内置 + 私有」双资源根的 registry.json + implementations/ | npm registry |
| **工具空间** | 当前工作区加载的工具子集，按需从仓库导入 | 后端 `storage/workspace_tools.json`（前端 zustand store 镜像，localStorage 仅作降级缓存） | `package.json` dependencies |
| **工具标签** | 分类筛选元数据，创建时 LLM 自动生成 + 用户可修改 | registry.json 中 tools[].tags | npm keywords |

工具空间早期只存 localStorage，换浏览器/无痕窗口后清单丢失，因此真实状态源已迁到后端（`GET/POST/DELETE /api/tool/workspace`），前端 store 启动时以后端为准并做一次性本地数据上传迁移。

### 1.3 三者关系

```
工具仓库 (全部工具)
    │
    │ 新建工具 ──→ 自动加入工具空间
    │ 从仓库导入 ──→ 加入工具空间
    │
    ▼
工具空间 (用户加载的工具子集)
    │
    │ 从空间移除 ──→ 不影响仓库
    │
    ▼
工具标签 (分类体系)
    └── 创建时 LLM 自动生成
    └── 用户可手动增删改
    └── 用于仓库浏览页筛选
```

## 二、架构设计

### 2.1 工具生命周期

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   创建工具                                               │
│   (ToolEditorView: 描述→MD→代码→调试→注册)               │
│      │                                                  │
│      ├──→ ① 注册到工具仓库 (registry.json)              │
│      │       · 保存 spec.md 到 definitions/             │
│      │       · 保存 tool.py 到 implementations/         │
│      │       · LLM 自动生成标签                          │
│      │                                                  │
│      └──→ ② 自动加入工具空间 (前端 store)               │
│                                                         │
│   工具在空间中:                                          │
│      · 用户点击查看详情/执行                              │
│      · 用户可从空间移除 (不影响仓库)                      │
│      · 用户可在仓库页删除 (同时从空间移除)                │

│   工具在仓库中:                                          │
│      · 可被搜索/标签筛选发现                              │
│      · 可被任何工作空间导入                               │
│      · 可被删除 (彻底清除)                               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 4.4 标签筛选

- **多选逻辑**：点击多个标签取交集（AND），显示同时拥有所有选中标签的工具

## 五、交互流程

### 5.1 从仓库导入工具

```
用户点击工具空间头部的 [📦 工具仓库] 按钮
  → 切换到仓库浏览页 (RepositoryView)
  → 浏览/搜索/标签筛选找到目标工具
  → 点击工具卡片上的 [+ 添加]
  → POST /api/tool/workspace，工具写入后端工作区间清单
  → 左边栏 "已加载工具" 列表刷新，按钮变为 [✓ 已加载]
```

### 5.2 创建新工具

```
用户点击工具空间头部的 [+ 创建新工具] 按钮
  → 切换到工具编辑器 (ToolEditorView)
  → 填写需求描述 → 生成 MD 规范 → 生成代码 → 自动调试 → 注册
  → 注册成功后:
      ① 工具写入私有根仓库 (registry.json + 文件)
      ② LLM 自动生成标签（异步）
      ③ 工具自动加入当前工具空间（后端工作区间清单）
      ④ 切换到工具详情页
```

### 5.3 从代码导入（规划中）

粘贴/上传已有 Python 代码、自动提取签名生成 MD 规范并注册的流程为规划项，尚未实现。

### 5.4 从工作空间移除工具

```
用户在左边栏工具项上点击 [×]
  → 工具从左边栏 "已加载工具" 列表中移除
  → 仓库中该工具不受影响
  → 可随时从仓库重新导入
```

### 5.5 从仓库删除工具

```
用户在仓库浏览页工具卡片上点击 [🗑️ 删除]
  → 弹出确认弹窗
  → 用户点击 "确认删除"
  → 调用 DELETE /api/tool/{id}
  → 后端删除:
      · resources/tools/registry.json 中的记录
      · resources/tools/implementations/{id}/ 整个目录
      · resources/tools/definitions/{id}.md
  → 前端:
      · 仓库列表移除该工具
      · 如果该工具已加载到工作空间，自动从空间移除
      · 刷新标签统计
```

### 5.6 查看工具详情

```
用户在左边栏点击工具项
  → 切换到工具详情页 (ToolDetailView)
  → 显示: 工具信息、代码、参数、执行按钮
```

## 六、标签系统

### 6.1 自动标签生成

工具注册时，LLM 根据工具信息自动生成标签。

**调用时机**：`POST /api/tool/register` 成功后，异步调用 LLM

**Prompt**：

```
根据以下工具信息，生成3-5个简短的中文标签（每个2-4字），
用于工具分类和检索。标签应准确描述工具的核心功能和适用场景。
返回 JSON 数组，不要其他内容。

工具名称: {name}
工具描述: {spec_md[:500]}

返回格式: ["标签1", "标签2", "标签3"]
```

**示例**：

| 工具 | 生成的标签 |
|------|----------|
| paper-summary | `["LLM", "文档", "PDF", "摘要"]` |
| image-resize | `["图像", "处理", "缩放", "格式转换"]` |
| csv-analyze | `["数据", "表格", "分析", "统计"]` |

### 6.2 手动标签编辑

- **位置**：工具详情页 (ToolDetailView) 标签区域
- **删除标签**：点击标签上的 × 图标
- **添加标签**：在输入框中输入新标签，回车确认
- **保存**：修改后自动保存到 registry.json
- **API**：`POST /api/tool/{id}/tags` body: `{"tags": ["标签1", "标签2"]}`

### 6.3 标签聚合

前端加载仓库时：
1. 遍历所有工具的 `tags` 字段
2. 去重排序
3. 统计每个标签下的工具数量
4. 按工具数量降序排列（常用标签在前）

## 七、API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/tool/list` | 获取仓库所有工具列表（含 `is_user_generated` 标记） |
| `POST` | `/api/tool/register` | 注册新工具 |
| `DELETE` | `/api/tool/{id}` | 删除工具（registry + 文件） |
| `POST` | `/api/tool/{id}/tags` | 更新工具标签 |
| `GET` | `/api/tool/repository` | 仓库工具（含标签统计） |
| `GET` | `/api/tool/workspace` | 工作区间已加载工具清单 |
| `POST` | `/api/tool/workspace` | 添加工具到工作区间 |
| `DELETE` | `/api/tool/workspace/{tool_id}` | 从工作区间移除 |

```json
// Request
```

## 八、前端状态管理

### 8.1 工具空间 Store (`workspace-tool-store.ts`)

```typescript
interface WorkspaceTool {
  id: string
  name: string
  tags: string[]
  loadedAt: string
}

interface WorkspaceToolState {
```
