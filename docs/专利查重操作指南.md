# 专利查重操作指南（手动检索 + 离线导入）

> 适用于 SOTABand「学术工具箱」下的专利查重 / 专利检索查重工具。
> 结论先行：**当前没有既免费、又稳定、还覆盖中文专利的联网专利检索 API**，
> 因此推荐「手动检索 → 离线导入 → 程序粗筛 + 大模型复核」这条零外部依赖的链路。

---

## 一、为什么不用联网 API（2026-09 现状）

| 通道 | 费用 | 门槛 | 覆盖 | 结论 |
|------|------|------|------|------|
| **Lens.org** | 免费档极有限，商用约 $1000/年 | 需 token | 全球 1.4 亿 | ❌ 已对非科研用户收费，token 失效 |
| **EPO OPS** | 免费 4GB/周 | OAuth 应用注册 | EP/WIPO | ❌ 注册流程繁琐 |
| **USPTO ODP** | 免费 | 需 ID.me 美国实名 | 仅美国 | ❌ 国内难实名 + 只覆盖美国 |
| **Google Patents 公开接口** | 免费 | 无 key | 全球含中文 | ⚠️ 会被限流（连续请求后 503） |
| **Google BigQuery** | 首 1TB/月免费 | GCP 账号 + 银行卡 | 最全含 CN 全文 | ⚠️ 门槛高 |

**结论**：不存在「零成本 + 零门槛 + 稳定 + 覆盖中文」的完美选项。
而专利代理人真实工作流本就是「检索系统导出 → 本地精比对」，
本项目据此落地为**离线链路**，贴合实战、零依赖。

> 补充：如果你发现"所有 API 都连不上"，先检查本机是否开了代理
> （`http_proxy` / `https_proxy` 环境变量，常见 `http://127.0.0.1:xxxx`）。
> 工具代码里的 `requests` 默认会走系统代理，代理没开/挂了会导致全部请求失败。

## 二、完整工作流（三步）

```
① 网页检索 + 导出 CSV  →  ② 离线导入语料库  →  ③ 程序粗筛 + 大模型复核
   (Google Patents 等)     (patent-corpus-import)   (patent-retrieval-check / patent-plagiarism-checker)
```

### 第 1 步：网页检索并导出

1. 打开 [Google Patents](https://patents.google.com/)（或 Espacenet、CNIPA 检索系统）。
2. 用关键词 / 分类号 / 申请人检索，可加字段限定：
   - `q="固态电池 液冷"`、`country=CN`、`before:publication:20240101`
   - 布尔：`AND` / `OR` / `-term`（排除）
3. 找到相关专利后，**导出 CSV**（Google Patents 结果页有「下载 CSV」按钮，
   上限 1000 条，含标题/公开号/发明人/日期等字段）。
4. ⚠️ 关键：CSV 默认**不含权利要求全文**。要拿到权项，需在检索系统里
   勾选/导出「权利要求 / Claims」字段，或逐篇打开详情复制权项。
   没有权利要求，查重只能走「说明书全文轨」，法律判定（新颖性/侵权）会缺失。

### 第 2 步：离线导入成语料库

用「**专利语料导入**」工具（`patent-corpus-import`）：

```
mode=import, src=./data/xxx.csv, name=在先专利
```

- 支持 CSV / TSV / JSON / XML / TXT / MD，自动探测编码与分隔符。
- 自动按公开号去重、规范化成「摘要 / 权利要求 / 说明书」分节的 md 语料库，
  落盘到 `./data/patent-corpus/<name>/`。
- 返回的 `missing_claims` 会告诉你几篇缺权利要求。

### 第 3 步：查重（两种工具任选）

**A. 专利检索查重（推荐，一步到位）** — `patent-retrieval-check`：

```
path=./我的申请.md, source=./data/patent-corpus/在先专利, top=5, ai=true
```

会输出：召回语料按相关度排序 → 程序粗筛打分 → 大模型语义复核
（逐篇风险等级 + 理由 + 规避建议 + 总体结论）。

**B. 专利查重（更细的特征级比对）** — `patent-plagiarism-checker`：

```
path=./我的申请.md, corpus=./data/patent-corpus/在先专利, mode=all, ai=true
```

`mode` 可选：
- `claims` 仅权利要求特征比对
- `full` 仅说明书全文重复率
- `both` 双轨（默认）
- `legal` 仅新颖性 + 侵权判定
- `all` 全部（推荐）

---

## 三、两个工具的分工

| 工具 | 定位 | 输入 | 输出 |
|------|------|------|------|
| `patent-corpus-import` | 语料获取与规范化 | 导出的 CSV/XML 等 | 标准化 md 语料库 |
| `patent-retrieval-check` | 检索→粗筛→大模型复核 | 待检文件 + 语料目录 | 相关度排序 + LLM 复核报告 |
| `patent-plagiarism-checker` | 特征级细比对 + 法律判定 | 待检文件 + 语料目录 | 逐特征风险 + 新颖性/侵权结论 |

三者关系：`import` 造语料 → `retrieval-check` 快速粗筛定位风险 →
`plagiarism-checker` 对高风险候选做逐特征的精确法律判定。

---

## 四、重要提醒

- **新颖性 vs 侵权是方向相反的判定**：本方增加了区别特征后可以具备新颖性，
  但只要仍完整覆盖在先专利的独立权利要求，侵权风险依旧成立。工具会分别给结论。
- 新颖性适用**单独对比原则**（不得组合多篇文献），侵权适用**全面覆盖原则**。
- 所有结论都是程序化近似 + 大模型语义判断，**不构成法律结论**，
  不能替代官方 FTO / 查新报告与专利代理师的专业意见。
- 权利要求全文是特征比对和法律判定的前提，导出语料时务必带上。
